# ADR-0022: حذف واقعی عضویت و نقش کاربر (استثنای Soft Delete)

**تاریخ:** 2026-09-27
**وضعیت:** پذیرفته‌شده (ثبت تصمیمی که در commit `56c4d6f` اجرا شده بود)

## زمینه
قانون پروژه Soft Delete برای همهٔ Entityها است. اما جدول‌های پیوند `user_organizations`، `user_branches` و `user_role_map` قید یکتایی (`user_id, organization_id` و …) دارند. Soft Delete یک ردیف پیوند باعث می‌شد **افزودن دوبارهٔ همان عضو** با خطای یکتایی شکست بخورد.

## تصمیم
- حذف عضو از سازمان (`DELETE /organizations/current/members/{user_id}`) و تغییر نقش‌ها، ردیف‌های **پیوند** را واقعاً حذف می‌کند.
- خود کاربر (`users`)، ملک‌ها، مشتری‌ها، بازدیدها و معاملات او حذف نمی‌شوند و `created_by` آن‌ها معتبر می‌ماند.
- پس از هر تغییر، `permissions_version` کاربر افزایش می‌یابد تا توکن‌های قبلی باطل شوند.
- ثبت رویداد حذف/تغییر نقش در **Audit Log عمومی** (Sprint 1) انجام خواهد شد تا ردپای تاریخی از بین نرود.

## پیامدها
- افزودن دوباره عضو بدون خطا کار می‌کند.
- تا پیاده‌سازی `audit_logs`، سابقهٔ عضویت‌های حذف‌شده فقط در لاگ برنامه است (بدهی فنی ثبت شد).
